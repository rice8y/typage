# Content

Metadata, collection schemas, routing, feeds, and search.

## Content Model

Pages declare build metadata with a Typst-native directive. Typage reads the directive as metadata, removes it from the body before compiling, and passes schema-defined fields to templates as first-class page fields:

```typst
#show: page.with(
  title: "Hello",
  description: "A first post",
  date: "2026-06-23",
  updated: "2026-06-24",
  weight: 10,
  expires: "2027-01-01",
  draft: false,
)
```

Project-like pages can use the alias `project.with(...)` and define collection-specific fields:

```typst
#show: project.with(
  title: "typshade",
  description: "A Typst package for visualizing multiple-sequence alignments in bioinformatics.",
  date: "2026-05-23",
  updated: "2026-06-30",
  languages: ("Typst",),
  links: (
    (label: "GitHub", url: "https://github.com/rice8y/typshade"),
    (label: "Typst Universe", url: "https://typst.app/universe/package/typshade/"),
  ),
)
```

Declare collection schemas in `content/config.typ`:

```typst
#let collections = (
  posts: collection.with(schema: (
    title: str,
    description: optional(str),
    date: optional(datetime),
    updated: optional(datetime),
    draft: optional(bool),
    tags: optional(array(str)),
  )),
  projects: collection.with(schema: (
    title: str,
    description: str,
    publishedDate: optional(datetime),
    updatedDate: optional(datetime),
    demoURL: optional(url),
    repoURL: optional(url),
    languages: optional(array(str)),
    links: optional(array(object((label: str, url: url)))),
  )),
)
```

`content/config.typ` is evaluated by Typst. Imports, shared definitions, computed schemas, and functions work normally. Typage supplies `collection`, `optional`, `array`, `dictionary`, `object`, `union`, `any`, and `url` schema helpers, including inside imported schema modules. Other schema values are actual Typst types, such as `str`, `int`, `color`, `content`, `length`, and `function`; validation compares `type(value)` with the requested type. Use `std.array` or `std.dictionary` for bare container types because their short names are schema helpers in configuration. `none` and `auto` match those exact values. For legacy content, a `datetime` schema also accepts strings.

Validation runs during discovery, so `doctor` and `build` apply the same rules before rendering. `array`, `dictionary`, `object`, and `union` validate nested values recursively. A function used as a schema must return `true` for valid values. `optional(type, default: value)` supplies a missing top-level field. For example:

```typst
#import "_shared.typ": common-fields

#let collections = (
  projects: collection.with(schema: common-fields + (
    title: str,
    caption: content,
    accent: color,
    rank: value => type(value) == int and value > 0,
    status: optional(str, default: "active"),
    links: optional(array(object((label: str, url: url)))),
  )),
)
```

Metadata expressions are evaluated once during discovery, with imports and definitions preceding the directive in scope. Templates receive native values through `page`, `current`, and page summaries, including content, colors, datetimes, functions, and other Typst values. The internal transport does not serialize these values to JSON. Feed/search export uses only representable scalar, datetime, array, and dictionary values; Typst-only fields are excluded from those exports rather than converted to misleading strings. Routing and publication fields must remain exportable. Imported schema and metadata dependencies participate in cache invalidation.

TOML front matter is still accepted for legacy content, but new pages generated by `typage new` use `#show: page.with(...)`. TOML `[extra]` is not supported; declare collection fields directly instead.

By default, future-dated pages and expired pages are not built. Configure this when needed:

```toml
build_future = false
build_expired = false
```

Nested directories become nested sections. For example, `content/posts/tutorials/intro.typ` belongs to section `posts/tutorials`.

The generated site package exposes section data:

```typst
#import "@local/typage:0.2.0": current, section, children, ancestors, siblings

#current.updated
#current.weight
#current.languages

#section("posts/tutorials").pages
#children("posts")
#ancestors(current)
#siblings(current)
```

Generated `@local/typage` and `@local/typage-theme` imports before the directive are retained for rendering but skipped during metadata evaluation: the site graph does not exist yet. Metadata must not depend on these generated packages. Put shared metadata constants and schema definitions in ordinary Typst modules instead.

## Permalinks

By default, Typage uses directory URLs:

```text
content/index.typ             -> /
content/posts/hello.typ       -> /posts/hello/
content/posts/index.typ       -> /posts/
```

You can opt into a global permalink policy in `config.toml`:

```toml
permalink = "/:section/:slug/"
```

Supported placeholders:

```text
:section   page section, for example posts/tutorials
:slug      page slug from metadata or filename
:path      source path without extension, for example posts/hello
:filename  file stem, for example hello
:year      YYYY from date
:month     MM from date
:day       DD from date
```

A page can override the global policy:

```typst
#show: page.with(
  title: "Release Note",
  date: "2026-06-24",
  slug: "v0-23",
  path: "/releases/:year/:slug/",
  aliases: ("old/release-note",),
)
```

Generated page objects expose stable routing fields:

```typst
#current.kind
#current.slug
#current.path
#current.file_path
#current.url
#current.canonical_url
#current.aliases
```

Alias pages are generated as redirects to `canonical_url`.

## Publishing Metadata

When feeds are enabled, Typage writes RSS and, by default, Atom feeds:

```text
/feed.xml
/atom.xml
```

Feed output is configurable:

```toml
feed = true
feed_path = "rss.xml"
feed_sections = ["posts", "projects"]
feed_limit = 0
atom_feed = false

[[feeds]]
path = "projects/rss.xml"
title = "Project Feed"
description = "Project updates."
link = "/projects/"
section = "projects"
limit = 0
```

`feed_limit = 0` means unlimited items. `feed_sections` filters the primary RSS and Atom feeds, while each `[[feeds]]` entry can target a single `section` or a `sections` list.

If `base_url` is empty, feed links are emitted as site-root-relative URLs. Set `base_url` before publishing when you need absolute feed item links. Typage can also write a sitemap and robots file:

```text
/sitemap.xml
/robots.txt
```

Default templates emit:

```text
<link rel="canonical" ...>
og:title / og:type / og:url / og:description
twitter:card / twitter:title / twitter:description
article:published_time for dated pages
```

## Search

When search is enabled, Typage emits `public/search_index.json`. The minimal starter keeps search disabled; add a search page and client script when you want site search.

Suggested optional layout:

```text
content/search.typ
static/search.js
```

The old boolean form remains supported:

```toml
search = true
```

For real sites, prefer the table form:

```toml
[search]
enabled = true
mode = "auto"      # auto | latin | cjk | ngram | ngram-only
ngram = 2          # useful for CJK text
include_body = true
include_headings = true
include_tags = true
include_taxonomies = true
compact = false    # true omits full body text from the JSON index
max_tokens = 2048
```

Search entries include:

```text
title / url / description / excerpt
tokens
headings[] with heading-local tokens
fields.title / fields.headings / fields.body / fields.taxonomies
```
